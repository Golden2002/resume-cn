# 决策记录

## D-001 自建，而不是给 RenderCV 写中文主题

**日期**：2026-11-23
**状态**：已采纳，**待 M1 结束时复判**

**背景**：同类项目已有成熟者。RenderCV 用 YAML 转 Typst 出 PDF，明确主张内容与设计分离；JSON Resume 从 2014 年起维护开放 schema，有主题生态与 ATS 评分接口；2025 年还出现了 claude-cv-factory 这类 YAML 加质检的封装。再做一个通用生成器没有位置。

**判断**：空位在中文简历的文档工程，具体是三件既有项目不做的事：

1. 中文排版规范的可机器判定（GB/T 15834—2011、GB/T 15835—2011、W3C《中文排版需求》都有明文条款，但没人把它做成简历工具的门禁）；
2. 中文简历的体例约束（两页预算、证件照、求职方向、教育背景含高中、荣誉与资质这类单行分区）；
3. DOCX 作为一等输出（国内招聘与申请表普遍要 Word，RenderCV 只出 PDF）。

**复判条件**（M1 结束时执行，写进 README 作为公开承诺）：若以下三条中有两条已被 RenderCV 生态覆盖，则转为给 RenderCV 写中文主题并停止自建：

- 能对中文标点与中西文混排做条款级检查；
- 能输出 DOCX 且分页与 PDF 一致；
- 有中文模板的页数预算与分区体例机制。

**当时的证据**：<https://github.com/rendercv/rendercv>、<https://jsonresume.org/media>、<https://github.com/yurictl/claude-cv-factory>

## D-002 默认字体用微软雅黑，仓库不分发任何字体

**日期**：2026-11-23 ｜ **修订**：2026-11-23（原写“默认思源黑体”，改为下方口径）
**状态**：已采纳

**背景**：原模板用微软雅黑，我们日常做的简历也都是雅黑。雅黑是商业字体，把它打进公开仓库是明确侵权；但反过来把默认字体改成别的，本地产出就与已成稿的版本不一致。这两个诉求可以同时满足：**仓库只写字体名，不发字体文件**。

**决策**：

1. 模板默认字体族为微软雅黑，本地产出与既有简历一致；
2. 仓库 `.gitignore` 排除 `fonts/`，任何字体二进制不入库；
3. 别人机器上没有雅黑时，两条路：`fonts install --to-user` 下载思源黑体（SIL OFL 1.1，打印 SHA256），或 `fonts define` 登记自己手上的任意字体；两种都用 `--font` 指定；
4. 字体是否真的被用上，由产物门禁比对 PDF 的 `BaseFont` 判定，不依赖转换器的口头报告。

**为什么第 4 条必要**：实测中，未装某字体时 LibreOffice 静默替换为 SimHei，PDF 看着正常、字体也确实嵌入了，但**页数从 2 页变成 1 页**。只查“字体是否嵌入”会漏掉这一类失败。

**为什么换字体不改版式**：行高写在 `lineHeightPt` 里是显式值。实测微软雅黑换成思源黑体（默认行高约高 9%），两页仍是两页，纵向坐标差 1pt 以内。

## D-003 schema 以 JSON Resume 为基线，中文扩展放 cn 命名空间

**日期**：2026-11-23
**状态**：已采纳

**决策**：字段命名沿用 JSON Resume（basics、education、work、awards、certificates、publications、skills、languages、projects），中文场景新增项一律放进 `cn` 子对象，不新造顶层字段。

**理由**：自创 schema 没人认识，也无法复用既有工具链。

**两条附加约束**：

1. **不收身份证号**。需要证明身份时用 `evidence` 指向扫描件。隐私门禁按 GB 11643 校验位判身份证号，避免把 18 位证书编号误判。
2. **日期与编号一律加引号**。YAML 会把 `2024.09` 解析成数字，18 位编号超出安全整数范围会丢精度。工具做兜底转换并提示，丢精度的直接报错。

## D-004 四层分离，个人陈述默认关闭

**日期**：2026-11-23
**状态**：已采纳

**四层**：`data/`（事实与变体）、`templates/`（模板清单）、`policy/`（内容选用，落在变体里）、`src/`（渲染与门禁）。

**关于个人陈述**：中文简历不需要开场自述，占版面且冲淡证据。因此：

- 默认不写；
- 只有招聘公告明确要求时才启用 `statement`；
- 启用后渲染器强制放在最后一个分区，有门禁 L4 专门检查；
- 有字数上限，默认 300 字，门禁 L5 检查。

**来源**：这条来自使用者的明确要求（2026-11-23），此前的简历把自述放在第二个分区且近九百字，属于体例错误。

## D-005 已知局限，不当作已解决

**日期**：2026-11-23
**状态**：长期有效

以下四条写进 README 的“已知局限”，避免被当成已经解决的问题：

1. 门禁判合规，不判好看，版面仍需人看。
2. ATS 往返只能证明机器读得对，不能证明招聘方会给面试。
3. 只有一路文本抽取器时是弱校验，报告里必须标注是单源还是交叉。
4. 身份证校验位只做格式判断，不保证号码真实存在。
